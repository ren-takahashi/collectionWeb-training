## 技術選定・構成方針

#### 使用技術
  - Next.js
  - TypeScript
  - Prisma（TypeScriptから安全にデータベースを操作するためのツール（ORM））
  - PostgreSQL
  - Docker

### 開発環境
- Next.js は WSL 上の Node.js（nvm）で実行する
- PostgreSQL は Docker Compose で起動する

#### 採用理由
- Next.js はローカルNodeでの開発がシンプルであり、開発体験が良い
- DBのみDocker化することで、環境差異を最小限にしつつ構成の複雑化を避ける
- アプリケーションまでDocker化すると、初期構築やデバッグコストが増えるため、初版では採用しない

---

#### 採用理由
- Next.js は Vercel との親和性が高く、設定なしでデプロイ可能
- 初期コストを抑えつつ公開までのハードルを下げることを優先
- 小規模な個人開発では、インフラ管理コストを避ける方が合理的

---

### Docker の扱い
- 初版では DB のみ Docker で管理する
- アプリケーション（Next.js）は Docker 化しない

#### 採用理由
- 開発環境と本番環境の完全一致よりも、開発効率を優先
- 本番環境が Vercel の場合、Dockerfile は不要となるため
- 必要になった場合のみ後から Docker 化できる構成とする

---

### 将来の拡張方針
- バックエンドを分離する場合は FastAPI 等を別サービスとして切り出す
- その際は API 経由でデータ取得を行う構成へ移行する
- 現在はそのために、Prisma の利用をデータアクセス層に閉じ込める設計とする
